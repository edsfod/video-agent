# Other agents and chat AIs with a file limit — user request (2026-10-28)

The user asked about pi, Hermes Agent and DeepSeek Harness (dsh), and about DeepSeek's web chat, which takes no zip and at most 50 files (Claude judgment on the design):

- **Other agents.** One more route, 其他 Agent, instead of a route per tool: the settings choose a preset or a command of the user's own, and the agent gets the task Codex gets (read the skill file and follow it, save through `summarize --import --source`). Presets, from each tool's own help (pi 0.99 and Hermes Agent 0.21 on the maintainer's machine) or README (dsh, in developer preview, not installed and not run): `pi -p` and `hermes chat --query-file - -Q` take the task on standard input; `dsh --profile headless {prompt}` takes it on the command line, so `{prompt}` becomes a line naming a temporary task file (cmd.exe keeps one line). The settings say that these agents run commands as the user, unlike Codex's sandbox and Claude Code's allowed tools. The window shows their output as text. Locating a program now prefers an `.exe`, then a `.cmd`: `where pi` lists the Git Bash script `pi` first, which cmd.exe cannot run.
- **Several other agents, each a route** (2026-10-28: on 0.8.2 the user could not find 其他 Agent, which showed only once the settings named one, and then asked for more than one; Claude judgment on the form). The settings have a row per preset and one for a command of the user's own, each ticked and its command editable, marked 已找到 or 没有找到; every ticked agent is a summary and collection route of its own, under its name. Until the user saves other choices, the presets found on this computer are ticked, as Claude Code and Codex show when found; a saved choice stays, and the 0.8.2 single choice carries over. With none, a 其他 Agent route still shows and says where to add one, and 生成总结 stays off.
- **The skill for agents without plugins** (user request, 2026-10-29: a button rather than copying by hand). 设置 → Agent 插件 copies `skills/video-agent/` to where each preset reads skills, found in their documentation on 2026-10-29: pi the Agent Skills folder `~/.agents/skills` (pi's skills.md); Hermes Agent `<HERMES_HOME>/skills` (default `~/.hermes`), one category folder deep, as its own skills are (Claude judgment: `media`); DeepSeek Harness `<dshHome>/skills` (`DSH_HOME`, default `~/.dsh`; the skill-source table inside its app). 复制到其他文件夹… copies into a picked folder for any other agent. Only a missing folder or an earlier copy is replaced, never another `video-agent` folder (such as a checkout of this project); copies are refreshed after an update like the plugins. In the app none of this is needed: the agents are told the skill file's path.
- **A model and a thinking level for each route** (user requests, 2026-10-29: not only the configured default, and for agents too; then a full list read without spending tokens, the thinking level, and drop-downs that fit the page). The summary page has 模型 and 思考强度 drop-downs under the routes, kept per route (`routeModels`, `routeEfforts`) and used for that route on the collection page too; 默认 means the route's own setting and 自定义… takes a typed name. The lists (`gui/src/models.js`), each read from what the agent keeps or prints: Claude Code has no list command, so its documented aliases and the current full names, with `--effort`; Codex its downloaded catalog `~/.codex/models_cache.json` with each model's reasoning levels (`-c model_reasoning_effort`); pi `pi --list-models` and `--thinking`; Hermes Agent the cached list of the provider its `config.yaml` names, and `--reasoning`; DeepSeek Harness the models its profiles list (it has no thinking option); the model API `video-agent models`, the provider's model list, a GET that costs no tokens, and `summarize --effort` (OpenAI-compatible `reasoning_effort`; for Anthropic an extended-thinking budget of 2,000, 8,000 or 24,000 tokens, Claude judgment). The model goes to `summarize --model`, `--model` for Claude Code and pi, `-m` for Codex and Hermes Agent, and a `--patch` file for DeepSeek Harness, which has no such option (its `agent-default-model` config is replaced whole, so its provider is read from `--dump-config` and kept). A command of one's own takes it where it says `{model}`; without a model, `{model}` and an option just before it are left out. The task's title and the summary's source name what was chosen. 复制材料 is the first route, as it needs nothing installed. Drop-downs everywhere are drawn like the text fields, with a thin chevron instead of the system's arrow.
- **Presets inside desktop apps** (2026-10-28, user report: DeepSeek Harness on D: was not found). DeepSeek Harness's installer adds nothing to PATH; its `dsh` is `resources\runtime\cli\bin\dsh.cmd` in the install folder. A preset not on PATH is looked for there, the folder taken from the app's uninstall entry (any drive) or the default install folders.
- **A folder for chat AIs with a file limit.** `pack --folder PARENT --max-files N` (default 50, DeepSeek's web limit as IT之家 reported on 2026-04-08; not an official figure) writes a new folder with 提示词.md and at most N−1 pictures, chosen as the model API route chooses them: every screen page and whole frame, alone or on 2x2 or 3x3 sheets (whole frames went in the room left until 2026-10-30, see chat-ai-evidence.md). Pictures have numbered flat names (one upload of one folder) and the prompt maps each to the times and paths to link. The third NJU lecture: 109 pages on 28 sheets and 21 whole frames, 4.3 MB, the slide text readable. The GUI's copy route has 导出文件夹 beside 导出 zip, with the limit remembered. A text-only material with local OCR was considered and left out: DeepSeek's 识图模式 understands images (IT之家, 2026-05-09), so the pictures can go as they are.
