# Cleaned transcript — user decision (2026-10-28)

Until 0.3.0 the rules said to correct mishearings "in your head, not in the file". The user asked for a cleaned transcript that replaces the original in use without overwriting it, a practice taken over from yanhe-agent's `fix`.

- `transcript.srt` and `.txt` stay as acquired. `video-agent fix VIDEO --replace WRONG RIGHT` keeps wrong -> right pairs in `corrections.json` and always rebuilds `transcript.clean.srt` and `.txt` from the original and the pairs (`src/video_agent/corrections.py`), so `--remove WRONG` and `--reset` take corrections back without loss; with no pairs left the cleaned files go. The command prints each changed line and names pairs that matched nothing, and holds the video lock.
- Where a cleaned transcript exists it is the one in use: `summary-context.md` is now written from the manifest and the transcript in use (`processor.write_context`), so a fix reaches every summary route without processing the video again; `show` reports it as `transcript` beside `transcript_original` and the pairs; the window's 字幕 tab shows it with a switch to the original and lists, adds and takes back corrections through the CLI. Processing again re-applies the pairs to a newly acquired transcript.
- Only words are replaced, never sentences, so the cleaned transcript is still what was said. A Latin word matches as a whole word (`react` leaves `reaction` alone); Chinese matches as written, so the rules and the skill say to list only forms that are wrong wherever they occur and to correct one-off mistakes in the summary only. Collections will share their terms (planned with collections).
