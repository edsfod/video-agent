# ADR-0015: 只用分阶段写总结，视频和文章都一样，文章用章节代替时间点

## 背景

- 分阶段把写总结拆成分单元、逐单元写、统筹全局几步，每个单元一个对话（[ADR-0010](0010-staged-through-agy.md)）。一次写整篇时，注意力被整段材料稀释，具体机制被压成一句概括：第 1 课里一段三分钟的隐蔽信道演示，一个对话写全篇只剩一句，分阶段写了 8 条命题（[staged-design.md](../staged-design.md)「代价」）。
- 总结的结构（单元、单元树、主线、推进边、提纲）由分阶段写出、程序读成数据（[ADR-0012](0012-flat-units.md)、[ADR-0013](0013-outlines-instead-of-a-linear-body.md)、[ADR-0014](0014-structured-summary-data.md)）。
- 总结文章要用同一套方法（`SUM-07`）。文章没有时间和画面，但同样是按顺序展开的材料：作者在一段连续的原文里围绕一点展开，章节代替时间点，指出条目在原文的哪里。

## 决策

1. **不保留一次写整篇的方式**（用户定）：Agent 应用自己写整篇、模型 API、网页 AI（复制材料、导出文件、DeepSeek 网页版全自动）都去掉。Agent 应用经 skill 进来时，只调用命令行跑分阶段。
2. **文章也分阶段写，结构和视频的相同**（用户定）：单元是一段连续的原文；条目标出所在的章节（例如「3.2」），代替时间点，不标页码；按顺序的提纲是原文顺序提纲；主线、旁支、单元树、前置部分都和视频的一样。
3. **文章的材料由程序先备好**：写总结的模型只能读工作文件夹里的文件，所以程序先把网页或 PDF 转成文字和图片放进文章的文件夹，相当于视频的「处理」。
4. **规则拆成共用的核心和各自的部分**：核心是总结给谁看、条目、来源、标签、拓展和核对、命题怎么写、单元树、主线；视频另有时间点、画面、字幕、课堂的需留意；文章另有章节、图表。分阶段各步的提示由这些拼成，核心改一处，视频和文章都变。

## 备选方案

1. **保留一次写整篇的方式，按新结构写**：「背景」第一条的问题照旧；几种方式各有一套检查和多轮复查，要和分阶段的读入、检查保持一致。
2. **文章做成放进别的 Agent 里的单体 skill，由那个 Agent 一次写完**：就是一次写整篇；不能运行代码的 Agent 还要自己写结构，模型自己写结构会随机漏（[ADR-0009](0009-program-lays-out-units.md)）。
3. **文章按线性的详细内容加要点、由程序从正文排出「主线与单元」**：被 [ADR-0013](0013-outlines-instead-of-a-linear-body.md) 否决的结构。
4. **写总结的模型自己读网页、PDF**：分阶段的模型只开看图一个工具，读不了工作文件夹以外的东西（[ADR-0010](0010-staged-through-agy.md)）；开放上网和运行命令，每个对话的外壳和行为都控制不了。

## 影响

- 写总结要装 `agy` 并登录；不装任何东西就能写总结的方式（复制材料）没有了。
- 合集总结和学习提纲只由一次写整篇的方式写，去掉以后怎么写待定（requirements.md「待定」）。
- 用户自己的模板（`SUM-03`）只给一次写整篇的方式用，分阶段只用自带的规则；所有方式共用一份模板（[ADR-0008](0008-one-template.md)）不再成立，去掉那些方式时改写 ADR-0008。
- 和现有实现还不一致的地方：一次写整篇的各种方式都还在（`summarize.py`、`packing.py`、DeepSeek 网页版、Agent 的任务文字、`forest.py`、导入时的检查和多轮复查）；分阶段的提示仍从模板里取规则；没有文章的命令。
