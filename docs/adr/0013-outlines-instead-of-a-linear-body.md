# ADR-0013: 不存线性的详细内容，由提纲加展开拼出全部内容

## 背景

- 知识部分由平铺的单元组成，层级只在单元内部（[ADR-0012](0012-flat-units.md)）。
- 一份总结里的条目同时带着几种结构：时间顺序、支撑关系、关于什么。一种排法只能摆出一种，其余的要靠别的视图。
- 一种视图值得存在，要么它是挑选，要么它明显换了排法；否则就是在复写正文。用 1.6.0 的规则写的第 1 课总结里，「主线与单元」收了详细内容 79% 的命题，篇幅是详细内容的 71%，单元的小标题就是详细内容的段落标题、顺序一样；早先的「时间线」也是按段复写详细内容。

## 决策

1. **单元是视图的组件**（用户定）：折叠时露出几项接口，点开显示整个单元。视图由程序用这些接口组合，模型不写视图（[ADR-0009](0009-program-lays-out-units.md)）。接口：

   | 接口 | 内容 |
   |---|---|
   | 起点 | 时间点；范围由程序算 |
   | 标题 | 短名 |
   | 头 | 单元自己让读者带走的：论证单元的结论，演示单元说明了什么，话题单元的一句话 |
   | 种类 | 论证、演示、话题 |
   | 归属 | 属于哪条主线，或者是旁支、挂在哪 |
   | 贡献 | 写在单元之间的推进边上：它对边的另一端有什么用，来源写清：讲者接上（附时间和转述），或总结者归纳 |
   | 代表画面 | 从单元的条目链接的画面里取 |

2. **不存、也不显示线性的详细内容**（用户定）。需要线性全文时（导出 Markdown、全文搜索），由程序把要点提纲全部展开生成。
3. **完备**（用户定）：任一提纲，把它的节点全部点开，按提纲的顺序拼起来，得到全部单元的全部内容。点开一个单元显示整个单元，所以这等价于每个单元在每个提纲里至少出现一次，由程序检查。
4. **各提纲在内容上等价，在摆出的关系上正交**（用户定）。一个提纲值得存在，当且仅当它摆出的关系是别的提纲都没有摆出的。挑选由折叠来做，排法由提纲来做。
5. **两个提纲回答两种问题**（用户定）：
   - 要点提纲回答讲了什么：把单元当作待接收的知识，用时间和归属来排；
   - 论证提纲回答为什么、怎么做：用单元之间的支撑和铺垫来排。

   论证关系和主线无关：支撑和铺垫可以跨主线，一条主线里也可以有不参与论证的单元。
6. **提纲**（用户定）：
   - 要点提纲：每条主线一组，组名是话题，下面按时间列出它的单元，一行一个，露出头；讲者说出的主结论标在它所在的单元那一行。从某个单元岔出的旁支缩进在那个单元下面；插在两个单元之间的、给整条主线做背景的，按时间放在同一层，标出是旁支。各组按它第一个单元的时间排。总结者归纳的主结论讲者没说过，不放进要点提纲，只做论证提纲里一棵树的根。
   - 论证提纲：单元按支撑和铺垫排成森林，一个单元放在它支撑或铺垫的单元（或归纳的主结论）下面，标出是哪种边，露出那条边的贡献和来源。铺垫画进来，因为先提出问题、再给出解法是「怎么做」的一半。不参与这两种边的单元各自成一棵只有一个节点的树，所以每个单元都在里面。「续」是讲者回到同一点，不是理由，不画。
   - 第一视图：元信息、须知、概要、关于这份总结，然后是要点提纲和论证提纲。
7. **露出几级**：提纲露出 0 级（单元的头）或 1 级（单元树的第一层），由读者切换，不按单元长短设阈值。1 级按边的种类分（用户定）：要点提纲露出「展开」的子节点，即这一点的各个方面；论证提纲露出「支撑」「反驳」「步骤」的子节点，即理由和步骤。
8. **重复出现只展开一次**：一个单元在同一个提纲里出现两次时（例如它支撑两个单元），只在一处展开，另一处写引用。
9. **头和贡献分开露出**：要点提纲用头，论证提纲用贡献。只露贡献，单元会只剩对别的单元的用处，丢掉它自身的道理。一个单元支撑或铺垫两处时，两处各露各那条边的贡献（用户定）。
10. **露出的接口要给出内容**：头和贡献写「结论是 X」，不写「讲了 X」。从视频外描述视频只用于概要（`SUM-06`）。
11. **点开单元**：单元在一个单独的窗口里打开，显示整个单元，点 × 回到原处；单元文字里引用了别的单元，点了在同一个窗口里换过去，可以退回。打开的单元始终是一棵树：头在最前，每个条目在它的父节点下面；同一父节点下，这个提纲关心的边排在前面（要点提纲是「展开」，论证提纲是「支撑」「反驳」「步骤」），其余在后，各自按时间（用户定）。

## 备选方案

1. **一个线性的正文，加两种视图**（按时间的「要点」、按逻辑的「主线与单元」）：视图在复写正文（见「背景」的测量）；要点改写时间段以后，又写成了每段一条的时间线。
2. **命题级的论证森林作提纲**：就是备选 1 里的「主线与单元」，复写正文；只收和别的条目有关系的条目，通不过完备。
3. **论证提纲只收参与论证的单元**：不论证的单元和旁支不在里面，通不过完备。让它们各自成为一棵只有一个节点的树就完备了。
4. **把论证结构并进主线提纲**（每条主线一组，组内按支撑排）：把讲了什么和为什么混在一个提纲里。在第 1 课一段 10 分钟的片段上，这样排出的主线把这一段的论点单元排成了另一个单元的铺垫，时间顺序也被打乱；论证关系跨主线时又只能写成引用。
5. **要点只列主线上的单元**（真正的挑选）：旁支在任何提纲里都看不到，通不过完备。
6. **按单元长短决定露出 0 级还是 1 级**：阈值没有依据，读者自己切换就够了。
7. **贡献作为单元的一项**：一个单元支撑两处时，对两处的用处不同，一项写不下。
8. **要点提纲全片按时间排，每条标出主线**：几条主线在时间上交错时，同一话题的单元被隔开（用户定）。
9. **单元点开后按时间平铺，关系用箭头标出**：条目之间的关系看不出层次；讲者先给证据、最后给结论时，结论落到最后。
10. **单元在提纲里原地展开**：展开的内容把下面的行推开，提纲的位置跟着变；从论证提纲点开的单元，在要点提纲那边也得跟着展开。

## 影响

- 新结构先只由分阶段写出（`SUM-02`），网页 AI 等方式以后再适配。
- 成稿存成程序能按单元、条目、关系读的数据，桌面程序按数据画组件（[ADR-0014](0014-structured-summary-data.md)）。
- 和现有实现还不一致的地方：
  - 别的方式写的总结仍是线性的详细内容加两种视图，由 `forest.py` 排「主线与单元」、给「要点」挂画面；
  - 别的方式写的总结，桌面程序显示 Markdown，再从 HTML 里找回要点的画面和条目的位置。
