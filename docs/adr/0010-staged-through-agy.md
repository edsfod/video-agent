# ADR-0010: 分阶段写总结，只经 agy 命令行

## 背景

- 一个对话写全篇时，写的人要同时记住整段字幕、看所有画面、自己复查：长视频后半段写得粗，复查的代价是整篇再来一遍。
- 判断上的长尾问题程序看不出，例如具体机制被概括成空话、`讲者接上` 失真、`拓展：` 复述视频后文讲的话。
- 拆成小问题时，每个问题要的上下文仍然很大：放在同一个对话里会互相影响，放进各自的对话又要重复传长上下文。
- 分阶段对通道的要求：只开看图一个工具；能在原对话里接着问；报出每次调用的用量；能同时跑几十个对话（用户定）。

## 决策

1. `summarize --staged` 由命令行自己跑：主对话读全片的字幕、分单元，每个单元一个对话同时写，程序检查后只把问题发回原对话改，最后主对话写全局的部分，程序组装后走同一个导入（用户定）。状态全是文件，断了接着跑。做法见 [staged-design.md](../staged-design.md)。
2. 通道只接 Antigravity 命令行 `agy`，不经任何 Agent 应用（用户定）。

第 1 课（100 分钟）上的结果和用量见 [staged-design.md](../staged-design.md)「代价」：成稿 94,325 字，一个对话写全篇是 19,880 字。

## 备选方案

1. **一个对话写全篇**：见背景第一条。
2. **没读完全片就按时间切块、自底向上合并**（用户定）：切块的边界对不上语义，会切断跨几分钟的例子和论证。
3. **先一次写出完整终稿再按段打补丁；或在前面加一层单向的纯文本清洗稿**（用户定）：都没有解决背景里的问题。
4. **经 Agent 应用的桌面版**：系统提示和工具都控制不了；Antigravity 桌面版一个对话写全篇读入 778 万缓存 token。
5. **网页 AI**：人手做不了几十个对话；DeepSeek 网页版消息之间至少隔 1 分钟，还会限流。

pi、Hermes、DeepSeek Harness 的命令行能不能限制工具、接续对话，没查过；claude、codex 命令行见 [roadmap.md](../roadmap.md)。

## 影响

- 只能用自带的「标准」模板（[ADR-0008](0008-one-template.md)）；合集总结和学习提纲不能用这种方式。
- 要装 `agy`，并用 Antigravity 桌面版的登录。
- 写得多，花得也多：用量见 [staged-design.md](../staged-design.md)「代价」。
