# ADR-0009: 视图由程序组合，模型只写判断

## 背景

- 总结的视图（提纲、主线视图、线性导出）都由单元组合而成（[ADR-0013](0013-outlines-instead-of-a-linear-body.md)）。
- 每个条目只在一处写全；同一个条目、同一个单元在各个视图里要对得上。

## 决策

1. 模型只写判断：单元的划分和起点、单元里的条目和条目之间的关系、单元的头、单元之间的支撑和归属、单元对主线的贡献和它的来源（用户定）。
2. 程序从这些判断组合出全部视图，编号、链接、画面、时间段都由程序带上（用户定）。
3. 组合不出来的报给写的人：关系里用了不存在的编号，接到主线的单元没写来源，有单元没出现在某个提纲里。
4. 用户自己的模板没有要求模型照这个格式写判断，程序不替它组合，交给写的人。

## 备选方案

1. **让模型自己写视图**：会漏掉有关系的条目、把一个条目写进两处、让视图和正文的关系对不上。规则写清了也会发生，是长输出里的随机遗漏，加措辞挡不住：同一模型、同一规则，一次漏、一次不漏。用 1.4.1 的规则写的三份稿子里，模型自己写的森林里的关系 71 条有 69 条也写在正文里，所以从正文组合出来不丢东西，还补回了模型漏掉的一棵树。

## 影响

- 模型写判断的格式成了模板的一部分，改格式要同时改组合它的程序。
- 和现有实现还不一致的地方：`forest.py` 从线性的详细内容里按关系排出「主线与单元」，并给模型写的「要点」挂上编号链接和画面（[summary-design.md](../summary-design.md)「主线与单元和要点」）；单元由关系树推出，不是由分单元得到的（[ADR-0012](0012-flat-units.md)）。
