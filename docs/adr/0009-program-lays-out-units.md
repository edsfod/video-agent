# ADR-0009: 「主线与单元」由程序照详细内容排，模型不写

## 背景

- 条目按关系组成森林，每个条目只在一处展开；主线写在最前（`PRM-J1`–`PRM-J14`）。
- 详细内容是正文，每个条目只写一次（`PRM-G1`）。

## 决策

1. 模型只在详细内容里写判断：命题行后面的关系（`← P1, P2`、`反驳 P4`、`步骤 P39`），以及主结论下面的 `接上：`。
2. `src/video_agent/forest.py` 照这些关系排出「主线与单元」，并给「要点」加上编号的链接和画面。排法见 [summary-design.md](../summary-design.md)「主线与单元和要点」。
3. 只在模板的「主线与单元」一节带着程序的标记时运行；没有标记的用户模板交给写的人。
4. 排不出来的报给写的人：关系里用了不存在的编号、接到主结论的条目没写来源。

## 备选方案

1. **让模型自己写这一节**：会漏掉有关系的条目、把一个条目写进两个单元、让正文和森林的关系对不上。规则写清了也会发生，是长输出里的随机遗漏，加措辞挡不住：同一模型、同一规则，一次漏、一次不漏。用 1.4.1 的规则写的三份稿子里，森林里的关系 71 条有 69 条也写在正文里，所以从正文排出来不丢东西；按根所在的段分组，和模型自己分的单元基本一致，还补回了模型漏掉的一棵树。
2. **把彼此没关系的树按话题并成一个单元**：等于为了凑单元编出关系。
3. **用段落标题当单元标题**：一段里可能有两棵树，第二棵会被标错。

## 影响

- 视频不论证时，条目之间没有关系，这一节为空，话题由详细内容的分段表达。
- 模型写关系的格式成了模板的一部分，改格式要同时改 `forest.py`。
