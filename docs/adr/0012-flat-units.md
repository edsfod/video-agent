# ADR-0012: 总结的知识部分由平铺的单元组成，层级只在单元内部

## 背景

- 总结分成前置部分和知识部分，知识部分由单元组成，单元由条目组成（`SUM-06`）。
- 单元同时是分阶段写总结的工作单位和状态单位：一个单元一个对话，状态按单元存（[ADR-0010](0010-staged-through-agy.md)）。
- 读者要能只看单元的头，也能往下看一层，还能看到全部（[ADR-0013](0013-outlines-instead-of-a-linear-body.md)）。这要求单元有层级，但层级放在哪里决定了结构有多复杂。

## 决策

1. **划分**：单元把全部条目分成互不相交的几份，每个单元占视频里一段连续的时间。模型写单元的起点，范围由程序从起点算到下一个单元的起点（用户定）。
2. **单元内部是一棵有序树**：根是单元的头，算 0 级；其余条目各有一个父节点，父节点在同一个单元里。边有四种：支撑、反驳、步骤、展开。「展开」指这个条目讲的是头（或父节点）的某个方面，但不支撑它。条目的层级是它在树里的深度，同一个父节点下的条目按时间排（用户定）。
3. **单元之间只有关系，不嵌套**（用户定）：
   - 支撑：一个单元的结论支撑另一个单元的结论，或支撑某条主线的主结论；
   - 铺垫：读懂后面的某个单元需要它（定义、问题的提出、背景设定），但它不是理由；
   - 归属：单元属于一条主线，或者是旁支，挂在一个单元上、两个单元之间或一条主线上；
   - 续：讲者隔了一段又回到同一点，后一段是另一个单元，用「续」连回前一个。

   后面的单元提到前面单元里的某个具体内容（例如一个数字），算引用，加链接，不是结构上的关系。
4. **自包含**：一个单元要满足
   - 一个头：能用一句给出内容的话说出这个单元让读者带走什么；
   - 内部闭合：单元里的每个条目都挂在这棵树上，结构上的关系不跨出单元；单元和单元之间只在头这一级相连；
   - 单独能读懂：只读这个单元，加上它引用的别的单元的头，就能读懂；
   - 时间连续；
   - 极大：和相邻的单元合起来就会有两个头。这一条由分单元的主对话判断，程序查不了。
5. **主线和旁支**（用户定）：
   - 有主结论的主线，成员是推进它的单元。删除检验：把单元拿掉，后面属于同一主线的单元读不懂，或主结论少了一条理由，它就推进这条主线（支撑、铺垫或续）。
   - 没有主结论的主线（话题），成员是讲这个话题的单元，由模型判断；单元之间可以有铺垫和续，不要求连通。
   - 旁支是由主线里某处引出、讲的是别的事、主线不依赖它的单元，挂在引出它的地方。
   - 有别的单元对它有推进关系的，不是旁支：旁支升成主线不另设判据。
   - 和哪条主线都无关的单元自成一条只有一个单元的主线，不设「其他」。
   - 一条主线可以有几个主结论：结论 B 以结论 A 为铺垫时，两者在同一条主线里。
   - 模型给每个单元写归属（属于哪条主线，或岔出自哪里）和推进边，主对话分单元时起草，写单元的对话可以在报告里提意见，统筹全局时定稿；程序查自洽：每个单元恰好一个归属；有单元对它有推进关系的不能标成旁支；「续」的两端在同一条主线；每条主线有话题；有主结论的主线，每个成员沿推进边能走到它的某个主结论，走不到说明漏了推进边或归属写错。
6. **生成顺序**：先读全片字幕分单元，再逐单元写条目（用户定）。
7. **插话**：讲者在一个单元中间插进别的话，短的并进所在的单元；长的把单元切成前后两个，后一个用「续」连回前一个（用户定）。

## 备选方案

1. **单元可以嵌套**：任何满足自包含的条目子集都可能是一个单元，可选的单元族落在条目集合的幂集里；每一层都要定在哪里停止细分，没有判据；关系还会跨层（大单元支撑另一个大单元里的小单元）。平铺时粒度只在分单元时定一次，层级由单元内的树给出，整体只有两层。
2. **一个单元由几段不连续的时间组成**：插话不用切开单元，但单元的范围不能再由起点算出，单元表和分阶段按单元存的状态都要改成区间的集合。
3. **先写出全部条目，再从中归纳出单元**：要先写全篇，注意力被几千行字幕和几十张图稀释，具体机制会被概括成空话（[ADR-0010](0010-staged-through-agy.md)「背景」）。「单元由条目组成」只作为数据上的关系。
4. **和头没有关系的条目不挂在树上**（不为条目编出关系）：单元是讲者围绕一点展开的，单元里的条目和这一点至少有「展开」这层关系，所以挂上不是编出来的；不挂上的条目在提纲里点不到，违反完备（[ADR-0013](0013-outlines-instead-of-a-linear-body.md)）。
5. **程序从推进边推出主线**（模型只给单元之间的边标种类，主线是推进关系下的连通分量）：漏标一条推进边，一条主线就被拆成两条，程序看不出来；模型写归属时，每个单元都要有一个，漏了查得出来。两种做法用同一个判据。
6. **和哪条主线都无关的单元归进「其他」**：把彼此无关的单元放进一组，等于为了凑组编出关系。
7. **一个主结论一条主线**：结论 B 以结论 A 为铺垫时，A、B 分在两条主线，读者顺着 B 读时要跳到另一条主线去找 A。
8. **没有主结论的主线也按推进关系的连通分量定成员**：讲同一话题的不同方面、彼此不依赖的几个单元，删除检验判它们互不推进，于是各成一条主线，和「主线是一个话题」不一致，主线提纲在这类视频上退化成时间提纲。

## 影响

- 分阶段的单元表每行带归属，推进边单独一节；写单元的人给每个条目写父节点（[staged-design.md](../staged-design.md)）。
- 和现有实现还不一致的地方：别的写总结方式写的仍是按段排的线性详细内容，单元之间的关系只有主结论下的 `接上：`（`SUM-02`）。
