# 总结

> 给谁看：要改总结的规则、模板或保存流程的人和 AI。回答：规则怎么组织、模板、「主线与单元」怎么排、「要点」上的链接怎么加、版本和谱系、画面集、导入时做什么和查什么。
> 规则要让模型做到的每一件事见 [summary-requirements.md](../summary-requirements.md)；几种写总结的方式（Agent、Antigravity、模型 API、网页 AI）见 [routes.md](routes.md)。

## 一、规则

- 一份规则，所有方式共用：`src/video_agent/prompts/summary.md`（`video-agent template` 打印），所以每种方式写出的是同一种总结。改规则先改 summary-requirements.md，再照它改；每条规则只写在一处，用中文（用户 2026-11-17 定）。
- 规则从三个原则推出，不针对某个视频出的毛病加特例（用户 2026-11-16 定）：
  1. **一个正文，两种视图。**「详细内容」是正文，每个条目只写一次、编号；「要点」（按时间）和「主线与单元」（按逻辑）只用编号指向正文。要点由模型写，每条写时间段和编号，不写画面链接；编号的链接和画面由程序从正文带过来（第三节）。没有「时间线」：详细内容的分段已经按时间排，要点按时间指向它们（用户 2026-11-20 定）。
  2. **每句话按它做什么归类。** 断言了什么的是命题，进详细内容；对观众的要求或告知是事项，进「需留意」，讲者为它讲的理由才是命题。
  3. **每个条目、每层关系都标明来源**：讲者、讲者引用的人、总结者。总结者加的分别写成 `拓展：`（读者缺的、视频没讲的）、`核对：`（出处对不对、支撑够不够）、`补全`（论证缺的前提）、`总结者归纳`。
- 篇幅跟着内容的价值走，不跟着视频花的时间；没内容的时间段直接略过，不用交代（用户 2026-11-16 定）。
- 规则不点名任何学科或视频类型；给模型的例子用占位符。
- 自查清单写在模板里。网页 AI 的结尾提醒和复查要求引用它（`templates.checklist`），所以用户自己的模板带着自己的清单；Agent 和模型 API 也能看到它。
- 讲者讲出的关系，写时间和转述，不加引号（用户 2026-11-20 定）：字幕是口语加语音识别，原样摘出来往往不成句，加了引号的转述又会冒充讲者的话。
- 已知没解决：`拓展：` 有时复述视频别处讲过的话。规则和自查都写了不许，结构上没找到原因，暂不处理（用户 2026-11-17 定）。

## 二、模板

- 自带一个「标准」（用户 2026-11-16 定）。用户的模板是 `%APPDATA%\video-agent\templates\` 下的 Markdown 文件。
- 和自带模板同名的，是用户改过的副本，处处代替自带的。副本第一行记着它来自哪一版自带模板：自带模板更新后，`template` 提示、`template --info` 报 `outdated`，并把新版写进 `templates\.defaults\` 供对比；`--accept` 记下已经合并。更新从不改用户的文件；从没改过的副本没有用户的东西，自动换成新版。
- 选模板：`template --use NAME`；`summarize`、`pack` 可以用 `--template NAME` 只指定这一次。桌面程序的任务记下加入时的模板交给命令行，并让 Agent 照 `video-agent template "NAME"` 写。
- `SKILL.md` 只读：每次更新都会替换插件文件，改了会丢；个人偏好写进模板。
- 桌面程序里：总结页的模板下拉框（合集总结和学习提纲也用它）；设置 → 总结模板（编辑、打开新版对比、已合并、恢复自带的、删除、从任一模板新建、查看 skill）。

## 三、主线与单元和要点

由程序照详细内容里的关系排出（用户 2026-11-20 定），模型只在详细内容里写判断，`src/video_agent/forest.py` 负责排版。

**模型写的**（都在详细内容里）：

- 命题行只写命题本身，一句话；场景、数字、做法写在子行。森林照抄命题行。
- 关系写在命题行的标签后面：`← P1, P2`（P1、P2 支撑它）、`反驳 P4`、`步骤 P39`（它是事件 P39 的一步）。
- 主结论下面一行 `接上：`，列出它从各单元接过来的条目和每层的来源：讲者把它连到主结论的，写时间和转述；讲者没这样连过，写 `总结者归纳`。只写在 `接上：` 里的连接也算一条支撑。
- 由总结者归纳的主结论，写进详细内容最后的「总结者归纳」一段，写出前提。
- 总结者自己展开的完整想法（拓展单元）不是条目，写在「主线与单元」里，标题 `` ### `拓展` <单元名> ``。

**程序排的**：

- 去掉主结论以后，有关系的条目连成一组组，每组排成一棵树，就是一个单元。根是没有条目在它之上的那条；有几条时，先取带步骤的事件，再取下面条目最多的，再取最先写的。树放在根所在那一段的标题下，各段按先后排。单元的标题就是根的命题行；段落标题只用来分组。和别的条目都没有关系的条目不进森林。
- 主线：`### 主线` 下是主结论，再列出接到它的每一条。来自单元的写「（来自单元：P<根>；<来源>）」，不带下级；引用和补全这类直接支撑主结论、不属于任何单元的，在主线里展开。接到主结论却没在 `接上：` 里写来源的，仍算单元的条目，并作为问题报出。
- 每个条目只展开一次：先在上层占好位置再往下展开，所以一个条目展开在它最高的位置，别处写「（在别处展开）」。站在上一条之上的条目照详细内容的写法写（`**P7** ← P5`）。
- 每个编号链接到详细内容里那一条（`[**P<n>**](#P<n>)`）；桌面程序点了会滚到那一条并短暂标出。
- 替换模型写的「主线与单元」，保留其中的拓展单元；模型没写这一节时，放在模板里下一节（详细内容）之前；什么关系都没有、也没有拓展单元时，没有这一节。
- 保存时运行：每次导入（Agent、网页 AI 的每一轮、导入文件），和 `summarize` 保存模型 API 的回答。只在模板的「主线与单元」一节带着标记 `video-agent: 这一节由程序根据详细内容生成` 时运行，自带的「标准」带着；没有标记的用户模板交给写的人，因为它们没要求模型照这个格式写正文。
- 排不出来的报给写的人：关系里用了不存在的编号，接到主结论的条目没写来源。

**要点**（用户 2026-11-20 定）：模型每条写时间段（`` `HH:MM:SS`–`HH:MM:SS` ``）、一句话和编号，不写画面链接。保存时程序：

- 把要点里详细内容中有的编号 `**P<n>**` 换成跳到那一条的链接 `[**P<n>**](#P<n>)`；详细内容里没有的编号照原样留着。
- 按这些编号在这一行里的先后（只认粗体编号，`P2P` 这类词不算），把这些命题在详细内容里链接的画面（命题行和它下面的子行上的，不含 `接上：`）带到这一行末尾，用 ` · ` 隔开；命题自己没有画面时，取直接在它下面的前提（`←`）或步骤的画面；同一张图只带一次。再保存一次时先去掉上次带上的，结果不变：要点行末 ` · ` 后面的画面链接都算程序带上的，模型自己写在那里的也会被去掉。要点也可以写成编号列表。
- 只在模板带着「主线与单元」的标记时做，和排「主线与单元」一起。桌面程序把要点行末的画面链接收到这一条下面，显示成一排小标签，点了打开大图。

画面只链接在正文的命题上，要点不另挑图，所以要点上的图和正文对得上。

**为什么不让模型写**：模型自己写森林时会漏掉有关系的条目、把一个条目写进两个单元、让正文和森林的关系对不上；规则写清了也会发生，是长输出里的随机遗漏，加措辞挡不住（同一模型同一规则，一次漏、一次不漏）。用 1.4.1 规则写的三份稿子里，森林里的关系 71 条有 69 条也写在正文里，所以从正文排出来不丢东西；按根所在的段分组，和模型自己分的单元基本一致，还补回了模型漏掉的一棵树。

**放弃的**：模型另取的单元标题；把彼此没关系的树按话题并成一个单元（等于为了凑单元编出关系）；用段落标题当单元标题（一段里可能有两棵树，第二棵会被标错）。视频不论证时，条目之间没有关系，这一节为空，话题由详细内容的分段表达。

## 四、版本和谱系

- 再写一次总结从不自动替换已有的（用户 2026-10-28 定）。当前的总结保留原名（`总结.md`、`合集总结.md`、`学习提纲.md`），所有链接、路线和合集都读它；其他版本是旁边的 `总结 (2026-10-28 15-30-12).md`，放在同一文件夹，`frames/…` 和 `../../` 链接照样能用。`<名字>.versions.json` 记每一版的时间、来源（模型 API · 模型、网页 AI、Claude Code、导入……）、备注、画面集和谱系。
- 新文字只在还没有总结、或明确要求时（`--make-current`、导入对话框的「设为当前总结」，默认不勾）成为当前的，否则存成一个版本。把某一版设为当前时，被替换的那版也存成版本；只有明确删除才删掉一个版本，当前的从不删。
- Agent 自己会写文件，所以 skill 也通过 `summarize --import --source` 保存。Agent 运行前桌面程序先把当前总结另存一份（`versions --keep`，已有一模一样的就不存）；结束后 `versions --settle`：别的文件已有同样文字的，这份副本删掉；Agent 直接改写了 `总结.md` 的，记为 Agent 写的。
- 谱系（用户 2026-11-16 定）：每份文字有一个改名也不变的 id，`based_on` 记它改自哪一版，从头写的记为空。导入时，新稿有五分之一以上的内容行和某一版一字不差（模板自带的行和「视频：」行不算），记为改自那一版，并提示一句；模型 API 总是从头写。网页 AI 后一轮覆盖自己上一稿时，id 和来源不变。Agent 的任务里写明不读已有的总结，除非用户的要求提到它。查出来的照抄不作为问题让 Agent 改，那只会教它换个说法。
- 总结页列出当前总结和各版本（时间、来源、备注、从头写或改自哪一版），能查看任一版、设为当前、写备注、删除。合集用同样的文件和命令。

## 五、画面集

- 每个视频有一棵画面集树（`pictures.json`，用户 2026-10-30 定）。根是处理得到的全部图片（代表画面、屏幕页、导入的课件）加上在网页 AI 轮次之外补截的；每个节点是从父节点去掉一些、加上一些图得到的一套。图片文件每张只存一份，节点只记路径。
- 有一个节点是「在用」的：每种写总结的方式和打包都只拿它的图，每个总结版本记下它用的是哪一套。选更早的节点就从那里重来。重新处理视频会开一棵新树（图片换了）。
- 网页 AI 的一轮从在用的那套长出一个新节点：去掉它说不用的、发过去但稿子没链接的，加上稿子链接的；补截的候选在被某一稿链接之前不属于任何一套。这样便宜的 AI 可以先筛图，好的 AI 再从剩下的写。稿子链接的图总在它那一套里。
- 链接和「不用」认 `frames/`、`slide-extraction/`、`slides/` 三个文件夹里的图。只认 `frames/` 时，链接的课件页会被当成发了没用而去掉（2026-11-20 修正；改正前留下的画面集有错的，已按用户的选择换掉）。
- 画面页显示总结页正在看的那一版用的画面集，否则显示在用的那套，只显示它里面的图，不用的点了才显示；在这里手动去掉或恢复一张，会生成一个新节点并设为在用。也可以选另一个节点设为在用。

## 六、导入

`summarize --import`（文件、`-` 标准输入，或不带值读旁边的 `总结.draft.md` 并在存好后删掉）把别处写的文字存成总结：

- 先把 `\r\n` 转成 `\n`（防 Windows 二次导入出现 `\r\r\n` 把代码块拆成逐行独立框），去掉包住整篇的 ```markdown 代码块；把网页 AI 改坏的链接改回相对路径（Gemini 把相对链接包进 Google 搜索，ChatGPT 放到它的沙箱路径下：链接里含有文件夹里确实存在的文件就改回来）；「视频：」那一行换成程序写的，「打开视频」能用。
- 取出 `## 字幕改正`（反复听错的写法），套进改正后的字幕；取出 `## 画面调整`（不用的图和要补截的时间段），按它截候选、调整画面集；链接写成 `补截:00:12:34` 的，按那个时间截一张图换上；截不到的改成 `补截失败:00:12:34`。
- 排出「主线与单元」，给「要点」加上编号的链接和画面（第三节）。
- 检查程序看得出的问题：缺了模板的哪几节、两分钟以上有讲话却没有哪一段覆盖的时间段（只提一次）、要点一条都没指到的段、时间点不在所在段范围里的命题、超出视频长度的时间点、「主线与单元」排不出来的地方。网页 AI 的轮次另查链接的图有没有说明（见 [routes.md](routes.md)）。
- Agent 的稿子查出问题时：稿子先存下，告诉它改什么，它改好后再跑同一条命令，覆盖刚存的那份，不另加版本；只有一次修改机会，之后剩下的问题照样报出，文字就这样留下。
