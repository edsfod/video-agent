# Summary versions — user request (2026-10-28)

The user asked that summarizing again never replace a summary on its own, and for a note on imported summaries; the mechanism was left to Claude (Claude judgment on the design, `src/video_agent/versions.py`):

- The current text keeps its name (`总结.md`, `合集总结.md`, `学习提纲.md`), which every link, route and collection reads. Every other version is a file beside it, `总结 (2026-10-28 15-30-12).md`, in the same folder so its `frames/…` and `../../` links still resolve; `<name>.versions.json` records each text's time, source (模型 API · model, 网页 AI, Claude Code, 导入) and note.
- A new text becomes current only when there is none, or when asked (`--make-current`, the import dialog's 设为当前总结, off by default); otherwise it is kept as a version and the window says so. Making a version current keeps the one it replaces as a version; only an explicit delete removes a version, never the current text.
- Claude Code and Codex write files themselves, so the skill saves through `summarize --import --source` like every other route, and the window keeps the current text as a version (`versions --keep`, skipped when an identical copy exists) before an Agent runs, so nothing is lost even if an Agent writes `总结.md` directly. When the Agent has finished, the window runs `versions --settle`: the copy goes if another file has its text, and a `总结.md` the Agent wrote over directly is recorded as the Agent's. Until 2026-11-16 `--keep` recorded the current text as the Agent's at once, so an Agent that saved through the import left the old text labelled as its own beside a duplicate (found on lecture 1 of 26生成式软件工程, 2026-11-16).
- **Where each text came from** (user decision, 2026-11-16, after an Agent asked to summarize the first NJU lecture afresh read the version before and kept 41% of its lines word for word, while four versions written apart shared none). The user asked whether the workspace was the problem: none of the Agent routes limits what an agent reads (Claude Code works in the whole workspace, Codex's sandbox limits writing only, Antigravity's `agentapi` takes no folder), and limiting it would not help, as the versions lie beside the material in the video's folder so that their `frames/…` links resolve. The user chose to record lineage instead, both 从头写 and 在某一版上改 (「总结版本也记谱系，并把「从头写」和「在某一版上改」都记下来」): every text gets an id that stays with it through renames and `based_on`, null for a text written afresh or the id of the version it was written from; an import sets it from the version sharing the largest part of its lines word for word, when that is at least 20% (template lines and the 视频 line left out), and says so; the model API routes write afresh. A later round written over its own draft keeps its id and source. The Agent task says not to read the existing texts unless the user's request names them. The summary tab shows 从头写 or 改自 <time>. A copy the import found is not made a problem for the Agent to fix, which could only teach it to reword (Claude judgment).
- The summary tab lists the current text and the versions (time, source, note), shows any of them with a banner, and makes one current, notes or deletes it. Collections use the same files and commands; their page shows the current text only for now.

Importing a chat AI's text (user reports, 2026-10-28) also repairs what chat AIs do to it: Gemini wraps relative links in a Google search and ChatGPT puts them under its sandbox, so a link whose search or path holds a file that exists in the folder is put back as the relative path; the 视频 line is replaced by the one this program writes, so 打开视频 works; and since a chat AI cannot run `video-agent fix`, the material asks it to list recurring mishearings under `## 字幕改正`, which the import applies to the cleaned transcript and removes from the summary. An imported summary of the first NJU lecture had 81 such search links; re-imported, it has none.
