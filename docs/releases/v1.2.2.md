1.2.2 让网页 AI 写的总结经过几轮复查，补上漏掉的内容。

**改动：**

- 网页 AI（包括「DeepSeek 网页」）写完第一稿后，程序一定再请它复查一轮：对照字幕逐段检查，讲者讲到的论点和理由、例子、数字、定义、条件、步骤、结论有没有漏写，时间点、链接的画面对不对，改好后输出整篇，并在最后写一节「复查」，列出补上了什么、改正了什么。只要复查还有补上或改正，就再查一轮，最多 6 轮。以前常常一轮就结束，第二轮也从不再要画面，总结里有错、有漏也没有机会再改。
- 每一稿导入时，程序会检查：缺了模板的哪几节，有没有写「画面调整」，字幕里哪些有讲话的时间段在详细内容里一段都没写到，有没有超出视频长度的时间点。查出的问题点名发给网页 AI，下一轮一并改掉。有意删掉的节、有意不写的时间段（课间、闲聊），网页 AI 在「复查」里说明原因就不再追问。拿以前的回答试过，查出过一份总结整整漏了 20 分钟。
- 「画面调整」现在每一稿都要写，没有要调整的写「无」，表示检查过了。字幕识别错的词要写进「字幕改正」，不写进「需确认」。
- 总结够不够详细，看讲到的内容是否都写到了，不看篇幅；提示词末尾原来要求「写成能快速扫读的笔记」，容易让它往短里写，已经去掉。
- 「总结」页不再预先选好一种总结方式，要你自己点一种；没选之前「生成总结」是灰的。以前装了 Claude Code 就默认选它，程序开着时又记着上次点的，看起来像随便选了一种。
- 「处理」页上 AutoSlides Extractor 的说明改成：没装时可以在「设置」里下载免安装版。

Claude Code、Codex 等 Agent 写的总结不经过这几轮。命令行里，`summarize --import` 导入网页 AI 的回答后会说明要不要下一轮、为什么，`pack --follow-up` 生成下一轮的材料。

**代码改动：**

- 命令行新增 `summary_review.py`：检查每一稿，读出「复查」一节，判断要不要下一轮，状态存在视频文件夹的 `summary-review.json`。`summarize --import` 从文件或粘贴导入时走这几轮（`--import` 不带文件名导入的 Agent 草稿不走），并接受 `--template` 指明按哪份模板检查。`packing.py` 的下一轮材料改为复查说明、查出的问题、补截的候选和上一稿。
- 桌面程序的 `chat-rounds.js` 按新的提示语进行多轮，导入时传入模板名。
- 文档：README 写上网页 AI 的多轮和 DeepSeek 网页，命令行部分精简，截图重拍；`docs/commands.md` 补全了以前缺的 `collection`、`fix`、`pack`、`versions`、`tools`、`show` 和十几个选项。
- 测试：新增检查的测试（缺节、没写到的时间段、超出的时间点，以及在「复查」里说明后不再追问），多轮测试改为复查到不再补上为止，桌面程序测试检查总结页一开始没有选中任何方式。

从 0.6.2 及以后的版本更新，只下载变化的部分。设置和工作区都保留。

- **桌面程序**：下载 `Video-Agent-Setup-1.2.2.exe`，直接运行即可覆盖旧版本。安装包没有代码签名，Windows SmartScreen 可能提示“未知发布者”，选“仍要运行”即可。
- **命令行工具**（需要 uv，不需要 git）：

  ```powershell
  uv tool install --force https://github.com/edsfod/video-agent/releases/download/v1.2.2/video_agent-1.2.2-py3-none-any.whl
  ```

  用 uv 安装时，FFmpeg 由 [imageio-ffmpeg](https://github.com/imageio/imageio-ffmpeg) 从 PyPI 提供；电脑上已有的 ffmpeg 会优先使用。`compress` 需要带 SVT-AV1 的 FFmpeg。

本页附有安装包里 LGPL FFmpeg 的完整源码（`ffmpeg-9.0.2.tar.xz`、`dav1d-1.5.4.tar.xz`、`SVT-AV1-v4.2.0.tar.gz`）和编译说明（`FFmpeg-BUILD.txt`），与 0.9.0 相同。
