# 意图与需求

> 给谁看：参与设计和实现的人和 AI。回答：要解决什么、怎样算做成、范围和约束。各部分怎么做见 [design/](design/)。

## 要解决的问题

看一个视频（课堂录像、讲座、访谈、教程、新闻）很费时间，而且看完记不住。用户要的是一份能代替看视频的笔记：视频讲了什么、要照办的事、日后能用上的内容，每一点能回到视频的时间点，画面上的内容也在里面。

## 怎样算做成

1. 任何来源的视频都能处理：本地文件直接处理；给链接时可以先下载，下载和处理是分开的两步。
2. 字幕先用已有的（视频自带的、旁边的字幕文件），没有时才用语音识别；音频上传到远程识别服务要用户同意。
3. 屏幕上出现过的每一页（幻灯片、代码、文档）都截到，用原始分辨率，一页一张；其余画面按间隔和场景变化抽取；写总结时能按时间补截。
4. 总结让没看过视频的读者知道视频讲了什么、记住要照办的事、日后能用上视频的内容：分得清哪些是视频说的、哪些是视频引用别人的、哪些是总结者加的；每一点能回到视频的时间点；画面上的文字、表格、图表读进总结。具体要求见 [summary-requirements.md](summary-requirements.md)。
5. 几种写总结的方式写出同一种总结，都按用户选的模板：Agent 应用（按 skill）、Antigravity 桌面版、模型 API、网页 AI（复制材料或导出文件，DeepSeek 网页版全自动）。
6. 同一个视频的每一版总结都保留，由用户决定用哪一版。
7. 几个相关的视频（一门课、一个系列、一个播放列表）组成合集，有合集总结和学习提纲，可以跟着播放列表自动下载新视频。
8. 桌面程序能完成以上全部操作；命令行工具也能，供 Agent 和批量处理用。

## 范围

- 只支持 Windows（用户 2026-10-27 定）。
- 由三部分组成，按需取用：命令行工具、Agent 插件（skill）、桌面程序。
- 总结文章：计划中，见 [design/article-summary.md](design/article-summary.md)。
- 不做：常驻的 MCP 服务；某个平台专用的逻辑（例如雁课堂的归 AutoSlides）。

## 约束

### 边界

- 桌面程序和其他前端都调用命令行工具，自己不含处理媒体或写总结的逻辑。
- AutoSlides Extractor 和 yt-dlp 通过它们的命令行调用，不复制它们的代码。
- 保持通用：别的工具的文件夹布局只作为有名字的约定加手动导入支持，不内置。

### 视频和下载

- `process` 接受任何本地视频路径，从不下载；`download` 单独、可选。下载器用 yt-dlp。
- 不修改、不移动源视频。例外：`compress` 用核对过、确实更小的副本替换（默认只替换本程序下载的；用户自己的文件要用户同意），`delete` 删除本程序下载的视频。用户从自己硬盘添加的视频从不删除。产物都放进工作区。

### 字幕

- 先用已有的字幕（视频内的字幕轨、旁边的字幕文件），再用可替换的语音识别；音频只有加了 `--allow-remote-asr` 才上传到远程识别服务。

### 画面

- 代表画面跟着视频走：每个不同的页面和场景都要有，不设固定的少数几张；高上限只用来挡住失控，到了会说明。不认为编码关键帧和场景变化本身有意义。
- 先识别画面布局；屏幕旁边或里面有摄像头画面时，只在屏幕区域里按原始分辨率找翻页。
- 屏幕页装了 AutoSlides Extractor 时由它找（先裁出屏幕区域给它，同一页逐步出现的几步合成一页），否则用本程序自己的翻页规则；`--no-extract-slides` 或 `AUTOSLIDES_EXTRACTOR=none` 关掉它。

### 依赖

- yt-dlp 和 FFmpeg 是 Python 依赖；安装包自带 yt-dlp 和自己编译的 LGPL FFmpeg（每次发布附上源码）。`PATH` 上已有的优先。
- 不安装别的工具：缺什么就说缺什么、怎么指定。唯一的例外：用户在设置里点了，才从作者的发布页下载 AutoSlides Extractor 的免安装版。
