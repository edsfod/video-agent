# 写总结的几种方式

> 给谁看：要改某种写总结方式的人和 AI。回答：Agent 应用、分阶段（agy）、模型 API、网页 AI 和 DeepSeek 网页版各怎么工作、为什么这样做。
> 总结的规则、模板、保存和检查见 [summary-design.md](summary-design.md)；DeepSeek 网页版和 agy 的实测行为见 [reference/](reference/)。

## 一、共同点

- 每种方式都按选定的模板写，规则是同一份，写出的是同一种总结（[summary-design.md](summary-design.md)）。
- 除了模型 API 由 `summarize` 直接保存，其余都经 `summarize --import` 保存（分阶段在命令行里调同一个导入），所以修链接、排「主线与单元」、检查、版本这些处理只有一处。
- 总结页上每种方式有自己的「模型」和「思考强度」下拉框，按方式分别记住（`routeModels`、`routeEfforts`），合集页也用；「默认」用这种方式自己的设置，「自定义…」可以手填。列表都从各工具自己存的或打印的东西读，不花 token（`gui/src/models.js`）。任务标题和总结的来源写明选了什么。
- 进总结页时不预先选方式：用户点了才选，没选时「生成总结」不可用（用户定）。「复制材料」排第一，因为它什么都不用装。

## 二、Agent 应用

- Claude Code（`claude -p`）和 Codex（`codex exec`）用用户自己的订阅，能自己补截画面。
- 其他 Agent：设置里每个预设一行，加一行用户自己的命令，各自打勾、命令可改，标「已找到」或「没有找到」；每个勾上的都是一种写总结的方式（用户定）。没保存过选择时，本机找得到的预设默认勾上。预设：
  - pi：`pi -p`，任务从标准输入传；
  - Hermes Agent：`hermes chat --query-file - -Q`，从标准输入传；
  - DeepSeek Harness：`dsh --profile headless {prompt}`，任务写进临时文件，命令行里只传一行指向它；
  - Antigravity 命令行：`agy --dangerously-skip-permissions -p {prompt}`（无人值守模式下会询问的操作一律被拒，所以要这个开关）；
  - 自己的命令：`{prompt}`、`{model}` 写在哪里就填在哪里；不选模型时去掉 `{model}` 和它前面的选项。
- 这些 Agent 以用户身份运行命令，不像 Codex 有沙箱、Claude Code 有允许的工具列表；设置里写明了这一点。
- 任务文字对所有 Agent 都一样（`gui/src/jobs.js`）：视频或合集在哪里、读 skill 文件并照做、命令行工具写全路径（Agent 的终端里不一定有它）、按哪个模板写、不读已有的总结（除非用户的要求提到）、写成草稿再用 `summarize --import --source` 保存、导入列出问题就改好再导入一次。
- 运行前后桌面程序用 `versions --keep`、`--settle` 保住原来的总结（[summary-design.md](summary-design.md)「版本和谱系」）。
- 模型和思考强度：Claude Code 用文档里的别名和当前的完整名称，`--effort`；Codex 读它下载的模型目录 `~/.codex/models_cache.json` 和每个模型的推理档位（`-c model_reasoning_effort`）；pi 用 `pi --list-models` 和 `--thinking`；Hermes Agent 读它 `config.yaml` 指定的服务商的缓存列表，`--reasoning`；DeepSeek Harness 读它各配置里的模型，没有思考选项，模型用 `--patch` 文件传（整段替换 `agent-default-model`，所以先从 `--dump-config` 读出服务商保留）；`agy` 用 `agy models`，`--model`，思考强度含在模型名里。
- 找程序：先找 `.exe`，再找 `.cmd`（`where pi` 先列出 cmd.exe 运行不了的 Git Bash 脚本）；预设不在 `PATH` 上时，按卸载信息里的安装目录（任何盘）或默认安装目录找，例如 DeepSeek Harness 的 `resources\runtime\cli\bin\dsh.cmd`。
- 没装插件的 Agent：设置 → Agent 插件把 `skills/video-agent/` 复制到各预设读 skill 的地方（pi `~/.agents/skills`；Hermes Agent `<HERMES_HOME>/skills/media`；DeepSeek Harness `<DSH_HOME>/skills`；`agy` `~/.gemini/antigravity-cli/skills`），「复制到其他文件夹…」复制到任选的文件夹。只替换不存在的或以前复制的，从不覆盖另一个叫 `video-agent` 的文件夹；更新后和插件一起刷新。在桌面程序里运行时不需要这些：任务里直接写了 skill 文件的路径。

## 三、分阶段（agy）

- 一种独立的方式（用户定，[ADR-0010](adr/0010-staged-through-agy.md)）：命令行自己跑 `summarize --staged`，经 Antigravity 命令行 `agy` 调模型，不经任何 Agent 应用。主对话分单元，每个单元一个对话同时写，程序检查后只把问题发回原对话改，最后主对话写全局的部分。做法见 [staged-design.md](staged-design.md)。
- 模型只有看图一个工具，不运行命令，读不了视频文件夹以外的文件（自定义 agent 加钩子）；外壳约 2,900 token。
- 总结页的「模型」是第一稿和主对话的，默认 `gemini-3.8-flash-high`；「修改轮」另选，默认 `gemini-3.8-flash-medium`；两个都能选「自定义…」手填。列表来自 `agy models`；思考强度含在模型名里。这种方式不收「对总结的要求」，总结页上不显示那个输入框（用户定）。
- 只能用自带的「标准」模板：选了别的模板时这种方式不可用，并写明原因。合集总结和学习提纲不能用这种方式。
- 只在找得到 `agy` 时可选（`winget install Google.AntigravityCLI`，用 Antigravity 桌面版的登录）。停止任务会结束命令行和它启动的 agy；再生成一次接着跑没跑完的部分。

### 分阶段接哪些通道

只接 agy 命令行。对通道的要求，以及其余通道为什么不接，见 [ADR-0010](adr/0010-staged-through-agy.md)。

## 四、模型 API

- `summarize` 把字幕和画面发给配置好的、能看图的模型：Anthropic，或任何 OpenAI 兼容接口（例如 ModelScope、本地 Ollama），写下结果。
- 服务商和模型支持工具调用时，模型可以要补截：它给出时间，`summarize` 截图发回去，模型接着写；不支持时只用事先抽好的画面。
- 发哪些图和网页 AI 的选法一样（「网页 AI」一节的总图排法），一次放不下就均匀去掉并说明。
- 模型列表 `video-agent models` 是服务商的一次 GET，不花 token。思考强度 `summarize --effort`：OpenAI 兼容接口传 `reasoning_effort`；Anthropic 用扩展思考，预算 2,000、8,000、24,000 token 三档。
- API key 存在 Windows 凭据管理器，从标准输入传给命令行，从不写进文件和日志。
- 总是从头写（谱系记为从头写）。

## 五、网页 AI

### 材料

- `pack` 生成给聊天 AI 的提示词：规则和模板、「视频：」那一行的开头、`summary-context.md`、结尾提醒（引用模板的「自查」，再加几条网页 AI 才有的事）。可以只要文字（复制到剪贴板），也可以连画面一起：`--zip`，或 `--folder PARENT --max-files N` 导出成文件夹（给不收 zip、有文件数上限的，默认 50）。
- 画面按文件夹里的原路径链接，导入后链接照样能用。每张发出去的图左下角印着 `#<编号> <时间>`，表里编号和路径对应，提示词让模型按印的编号认图：模型会按上传顺序对表，认错图。印字用 5×7 的点阵字体叠上去，因为自带的 FFmpeg 没有字体库。
- 放不下时拼成总图，按顺序取第一个放得下的排法：屏幕页单张、整幅画面单张；屏幕页单张、整幅画面 2×2；都 2×2；屏幕页 2×2、整幅画面 3×3；都 3×3。屏幕页带字，总放得比整幅画面大。3×3 也放不下时才均匀去掉一些并说明。总图只在发送时临时生成，表和链接仍写每张图自己的文件；提示词说明一格是一张图，按格里自己的编号和时间区分。DeepSeek 在 2×2 和 3×3 的总图上都读对了图上的数字和图表（2026-10-29 实测）。
- `summary-context.md` 把字幕行按当时屏幕上的画面分组（`▶ screen page from HH:MM:SS: <路径>`），模型看到什么就链接什么，不用自己对时间。

### 画面调整和补截

- 带画面的材料让模型在总结最后写 `## 画面调整`：用不上的写 `不用：<路径>`；缺图的写 `补截：<开始>–<结束> <要看到什么>`，没有要调整的写「无」。规则让它从字幕推测哪里屏幕上有东西而附的图里没有（读出一串数字、描述一张图表、逐条念文件、「看这里」），宁可多要。
- 对每个补截的时间段，截最多四张互不相同的候选：从同一画面持续的若干秒里取，先取持续最久的；时间段里有停住 2 秒以上的画面时只取这种。只给一个时间点时取它之后 10 秒。候选在被某一稿链接之前不属于任何画面集。
- 发过去但稿子没链接的图，从这一轮的新画面集里去掉；没发过的留着以后判断（[summary-design.md](summary-design.md)「画面集」）。所以发出去的图都要成功上传，一条消息不能少了图（「DeepSeek 网页版」）。

### 多轮复查

- 第一稿之后至少一轮复查：模型对照字幕把上一稿过一遍，补上漏掉的、删去不值得写的，结尾写 `## 复查`，逐条列出这一轮的 `补上：`、`改正：`、`删去：`，故意删掉的节 `删掉的节：`，要点不收的段 `要点不收：<段>（为什么）`，以及每张链接的图上有什么字幕里没有的 `画面：<路径> <内容>`。
- 每一稿导入时检查（[summary-design.md](summary-design.md)「导入」），另外查每张链接的图有没有 `画面：` 那一行：写「无」的，去掉链接并把图记为不用；没写的，下一轮点名。查出的问题在下一轮按名字发回。
- 比较每一稿和上一稿（不计空行和空格）：`补上`、`改正` 只在稿子真的变了时才算，状态里说改了多少行。
- 轮次继续的条件：复查补上或改正了什么、检查查出了问题，或者要了画面；最多 6 轮（DeepSeek 网页版的上限在按钮旁边设）。复查说没变化、检查通过、不要画面，就结束。复查要的是值得记的内容，不是每段讲话都写；没覆盖的讲话时间段两分钟以上才提，只提一次（用户定）。
- 后一轮覆盖前一轮：覆盖这次轮次最后写的那份文字（当前的或某个版本），前提是它还和轮次写的时候一样（`summary-review.json` 记着摘要），且是同一个模板。其余都是新文字：第一稿、收敛之后的回答、手改过的、换了模板的、别的方式写的。每一轮的备注以「未收敛」或「已收敛」结尾。中途断掉的保留最后一轮，同一视频同一模板的下一次运行在新对话里接着跑（`pack --resume`），轮数接着数。
- `pack --follow-up` 生成下一轮：复查要求、检查结果、候选和保存的上一稿。对话太长（从第一条消息起超过 100,000 字，讲座大约 4 轮）时，下一轮去新对话（`--new-chat`），只带需要的：规则、字幕、在用的画面、这一轮的候选、要求和上一稿；以前的回答和思考都不带。每条消息都会让模型把整个对话重读一遍。

## 六、DeepSeek 网页版

- 在桌面程序的窗口里像人一样用官方页面 chat.deepseek.com，用户在里面登录一次，登录状态存在它自己的会话里；不用逆向的接口（[ADR-0011](adr/0011-deepseek-official-page.md)）。
- 一个任务一个窗口，共用同一个登录；结束了的窗口给下一个任务用。它们和其他总结任务一起算进总结的并发数（设置 → 总结，默认 2）。
- 一轮：`pack --folder`，附上所有图，输入提示词，开深度思考和智能搜索（搜索用于 `拓展：`），页面用英文（用户定），等回答写完，读回答的代码块，`summarize --import`，有需要就 `pack --follow-up` 进下一轮。第一份总结是当前的，后面的轮次覆盖它；已有总结时每一轮是一个版本，备注「第 N 轮」。
- 发送和读取的可靠性：
  - 上传失败的图，点它卡片上的重试；Server busy 重试三次仍不行，按限流等；其他失败算这条消息失败。一条消息从不缺图发出：失败就整条重发，还不行任务失败，什么都不导入（用户定）。
  - 回答 3 分钟还没开始，按繁忙处理，重新加载对话页、重新附文件、重新输入；繁忙提示、上传 5 分钟没完成也一样，最多三次，繁忙提示后先等 30 秒。
  - 发送前给页面上已有的回答块做记号，新回答是最后一个没记号的块；回答要等服务器确实回应了这条消息才算；读两次、隔 1.5 秒、两次一致才算读完。
  - 对照这条消息实际发出的请求核对：新对话没有父消息、提示词在、每个文件都附上了；不对就重发。失败任务的窗口关掉。
  - 被拒绝发送太频繁时，所有窗口一起等，5 分钟起、翻倍到 30 分钟，等多久都行，之后接着发同一条消息；所有窗口的消息之间至少隔 1 分钟。
  - 程序启动时关掉 Chromium 的 `CalculateNativeWinOcclusion`，DeepSeek 窗口不节流：否则窗口被遮住、最小化或在屏幕外时页面不绘制，读回来的回答不完整。
  - 导入失败时，回答写进任务日志。
- 合集总结和学习提纲不能用这种方式。
- 页面的实测行为（限流的信号、上传和繁忙的表现、怎样用脚本查页面）见 [reference/deepseek-web.md](reference/deepseek-web.md)。
