# 桌面程序

> 给谁看：要改桌面程序（`gui/`）的人和 AI。回答：界面怎么组织、任务队列和并发规则、自动处理、终端、日志、托盘、设置。
> 各模块管什么见 [ARCHITECTURE.md](../ARCHITECTURE.md)；网站账号见 [processing-design.md](processing-design.md)；更新和安装包见 [distribution-design.md](distribution-design.md)；写总结的方式见 [routes-design.md](routes-design.md)。

## 一、技术和边界

- Electron，终端用 xterm.js 和 node-pty（VS Code 在 Windows 上用的组合，经 ConPTY），见 [ADR-0001](adr/0001-electron-and-checked-js.md)。
- 桌面程序把命令行当子进程运行，自己不含处理媒体或写总结的逻辑（[ARCHITECTURE.md](../ARCHITECTURE.md) 不变量 `A1`）。
- 代码是 JavaScript：`tsc` 借 JSDoc 检查主进程和页面的全部代码（严格模式，含空值检查；不要求每个参数都标类型，`catch` 到的错误是 `any`），不编译（[ADR-0001](adr/0001-electron-and-checked-js.md)）。页面用 `<script type="module">` 从 `file://` 加载 ES 模块，没有构建步骤。
- 页面和主进程之间不设白名单：页面能让主进程运行任何命令行命令，`shell:open` 能打开任何路径（[ADR-0002](adr/0002-no-allowlist-for-the-page.md)）。
- 队列放在主进程，不在页面里：页面重新加载也不丢，关窗口后在托盘里继续跑；重启后不保留排队中的任务。

## 二、任务队列和并发

任务是共享文件的独立进程。各任务写什么、读什么：

| 任务 | 写 | 读 |
|---|---|---|
| `download` | `<工作区>/下载/<标题> [<id>].<扩展名>` 和字幕（yt-dlp 先写 `.part`） | 网络 |
| `process` | 视频文件夹里的 `frames/<run>/`、`slide-extraction/<run>/`（每次新建）、`transcript.*`、`summary-context.md`、`manifest.json`、临时的 `.embedded-subtitle.srt` 和 `.audio-for-bcut.m4a` | 源视频、上次的清单和字幕 |
| `frame` | `frames/extra/frame-HH-MM-SS.jpg` | 源视频 |
| 各种写总结的方式 | `总结.md`，有时补截 | 清单、`summary-context.md`、画面 |
| `show`、窗口的各个视图 | 不写 | 以上文件 |

文件夹按视频路径的哈希命名，不同视频从不共用文件。由此：

- 可以同时跑：下载和任何任务（同一个链接除外）；不同视频的任何任务；`frame` 和任何任务。
- 不能同时跑：同一视频的处理和总结（固定的临时文件名、总结读到写了一半的材料、两个写 `总结.md` 的）；同一链接的两次下载（同一个 `.part`）；有任务在跑时换工作区（结果落到窗口不再看的地方）。
- 能同时跑但有代价：几个处理共用 CPU（FFmpeg 会占满）；几个 Agent 总结各花各的订阅额度。

怎么保证：

- 命令行（所有前端都受益）：`process`、`summarize`、`fix` 持有 `<文件夹>/.lock` 的系统锁；第二个写的人等 2 秒后放弃并说明（Windows 释放被杀进程的锁要一会儿）；进程被杀锁也随之消失。`transcript.*`、`summary-context.md`、`manifest.json`、`总结.md` 先写到唯一的临时文件再改名，读的人看不到半个文件。`frame` 经临时文件保存、不加锁，因为 Agent 写总结时会调用它。skill 让 Agent 遇到锁的提示就报告，不重试。
- 桌面程序的队列（`gui/src/tasks.js`，纯函数，`gui/test/tasks.test.js` 不依赖 Electron 测试）：忙的时候不拒绝，任务排队，状态有排队中、运行中、完成、未完成、已停止。每种任务一个池，在设置里改（默认：下载 3、处理 1、总结 2、压缩 1）；补截不限。DeepSeek 网页的任务算总结，各自一个窗口。每个视频同时最多一个处理或总结任务（也管住了不经命令行写 `总结.md` 的 Agent）。同样的工作（同种类、同目标）排着或跑着时不再加。按加入的顺序开始，要等的不挡后面的。有任务时不能换工作区。
- 底部的任务面板列出任务，能看任一任务的输出、停止或重试；排着和跑着的任务有勾选框，「停止所选」停勾上的，「全部停止」（先问）停所有的。托盘显示运行中和排队中的数量；侧栏的合集显示其中视频的任务数。

## 三、自动处理

- 「下载或添加后自动处理」默认开，记住选择：下载保存的每个文件、从本地添加的视频，按窗口的画面设置和必剪设置排一个处理（不带课件）。下载时发现已经存在的文件不再处理：`download --json`、`collection update --json` 给每个路径标出是不是新的。
- 「没有字幕时用必剪转录」默认开，下载后的处理也用它；勾选框说明音频会发给 B 站。从本地添加、没有字幕的视频先问（[processing-design.md](processing-design.md)）。

## 四、界面

- 侧栏只列合集，带各自视频的任务数；视频从合集页打开，视频页有「← 合集 · 第 N 集」返回。不在任何合集里的视频列在「视频」下。再点一次已打开的视频或合集就关上它，回到开始页。启动时不自动打开任何东西；合集读到之后才画列表，免得视频先在「视频」下闪一下。
- 视频页的标签：处理、字幕、画面、总结、终端。处理页显示 `layout.jpg`，可以拖出屏幕区域重新处理；字幕页显示在用的字幕，能切到原字幕，列出、添加、撤回改正；画面页见 [summary-design.md](summary-design.md)「画面集」；总结页见 [routes-design.md](routes-design.md) 和 [summary-design.md](summary-design.md)。
- AutoSlides Extractor 的勾选框说明写总结不需要它，`tools` 找不到时变灰并说明；字幕卡片写明来源（B 站 AI 字幕、同名字幕文件、某种语言），悬停显示文件名。
- 外观：跟随系统、浅色、深色（`nativeTheme.themeSource`），选了立即预览，保存设置才留下。
- 设置：右上角 ×、Esc、点外面，没改动时直接关；有改动时始终可见的保存行显示「有改动还没保存」和「不保存」「保存」。skill 查看器和日志点外面也会关。
- 下拉框画得和文本框一样，用细的箭头，不用系统的。
- 不弹通知和气泡。
- 删除：视频页「删除…」，视频列表旁「选择」多选后一起删，一次确认说明会删掉多少文件；有任务排队或运行中的视频不许删。`video-agent delete` 删掉视频的每个处理文件夹（路径指向它的、清单里写着它的；正在被运行中任务持有的文件夹拒绝删），把它从各合集移除；视频文件和旁边的字幕、信息文件只在本程序下载的（在工作区的「下载」或跟随的合集的下载文件夹里）时才删，用户自己添加的保留。

## 五、终端、日志、托盘

- 内嵌终端：从已装的 PowerShell 7、Windows PowerShell 5.1、命令提示符、Git Bash 里选，在视频的工作区文件夹里打开，可以跑命令行工具，或交互式的 `claude`、`codex`。打开终端标签不自动启动，点「启动终端」才启动，之后变成「新建终端」。
- 日志：`<userData>/logs/main.log`（5 MB 滚动），每个任务一个文件（保留最新 200 个），在「日志」窗口里看；传 API key 的标准输入从不写进日志。命令行查询失败也记进主日志。
- 托盘：关窗口只是隐藏，任务继续跑（设置，默认开）；再启动一次会显示已有的窗口。

## 六、和命令行的数据

- 命令行的 JSON 类型由 `contract.py` 定义，桌面程序用生成的 `cli-types.d.ts`（[design.md](design.md)「接口契约」）。
- 合集列表一次只读一份，同时来的请求共用之后的那次读取；读失败时保留已显示的合集，在侧栏说明，5 秒后再读。
