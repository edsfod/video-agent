# 合集

> 给谁看：要改合集、跟随播放列表、合集总结或学习提纲的人和 AI。回答：合集怎么存、怎么写合集的文字、窗口里怎么用、怎么跟随播放列表。

## 一、是什么

几个相关的视频按顺序组成合集：一门课、一个系列、一个播放列表、一个工作坊。什么都不假定是课堂。平台那一侧（在雁课堂上找课、快速字幕、下载）归 AutoSlides。

## 二、存储和命令

- `<工作区>/合集/<名字>/collection.json` 记成员顺序、共用的改正、跳过的视频和原因、跟随的来源；合集自己的 `合集总结.md`、`学习提纲.md`（带自测题）放在旁边，用 `../../<视频文件夹>/总结.md` 链接各集的总结。视频保留各自的文件夹。
- 命令：`collection create|add|remove|show|delete|skip|terms|list|follow|update`。`show` 报告每集是否处理过、是否有总结、时长、讲话占比和 `maybe_empty`（不到 120 秒或讲话不到 10%）；`skip --reason` 记下为什么略过。`show` 和 `list` 还给出 `overview_behind`、`guide_behind`：总结比合集总结或学习提纲新的那些集（按修改时间），合集页在文字上方提示。
- 共用的改正（`terms`）存在每个成员上（包括还没处理的），和视频自己的改正并列，所以退出合集就带走；同样的写法以视频自己的为准。
- `download --playlist --collection NAME --workspace WS` 按顺序填满一个合集。

## 三、合集的文字

- 合集总结和学习提纲从各集的总结写，各集总结已经链接了画面，所以不用发图。方式：`summarize --collection NAME [--guide]` 用模型 API（有没跳过、又没有总结的集时拒绝）；`pack --collection` 和 `summarize --collection --import` 给网页 AI；Agent 按 skill 的「A collection」做，可以把几集分给子 Agent。DeepSeek 网页版不能用。
- 合集总结有「需留意」一节和一列（从各集收集的截止时间、任务、提醒、通知）和跳过的视频一节；学习提纲有重点（讲者强调的，例如考试提示）、各主题和折叠了答案与出处的自测题。规则在总结模板里（[summary-design.md](summary-design.md)）。
- 版本和单个视频的总结一样（[summary-design.md](summary-design.md)「版本和谱系」）；合集页只显示当前的文字。

## 四、窗口

- 合集页列出各集和状态（打开、略过并写原因、移出），从视频列表（先给个选项，免得误加）或文件添加视频，给缺处理或缺总结的集排任务，按选的方式写合集总结或学习提纲（每个合集同时只有一个这类任务），显示两份文字（链接能打开某一集的总结），编辑共用的改正。视频页有「加入合集…」。一切都经命令行。
- 粘贴的链接代表一个列表时：`download` 不加 `--playlist` 什么都不下，加 `--json` 打印 `{"playlist": {url, title, count, titles}}`；窗口问要不要下整个列表，默认放进一个以列表命名的合集。B 站的快速检查不给每集标题，所以只显示标题和数量。
- 一个视频按加入时的路径或命令行解析出的路径对上合集里的条目（短的 8.3 文件名会被解析成长的）。

## 五、跟随播放列表

- 合集可以记下来源：列表的链接和下载文件夹（`collection.json` 的 `source`）；旁边的 `downloaded.txt` 是 yt-dlp 的下载记录，所以 `collection update` 只下以前没下过的、加到最后，「没有新的」是正常结果。`download --playlist --collection --follow` 第一次下载时记下来源并填好记录；`collection follow NAME URL` 给已有的合集加来源，第一次更新只记下已有的文件。
- 窗口里：列表的询问框提供「跟随」（默认开）和「程序开着时每六小时自己检查」（默认关，也在托盘里检查：可能触发大批下载）；合集页显示列表、上次检查和结果、「检查新视频」和同样的开关。一次检查是一个下载任务（网站登录照用，「下载完自动处理」处理新视频），不切走用户正在看的页面。
- 删除视频后，下载记录里仍有它的 id，更新不会再下回来。

## 六、不做

- 课件导出成 PDF（AutoSlides 做）；问「最近讲了什么」的单独命令（Agent 从总结回答）。
