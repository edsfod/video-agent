# 写作规范：仓库里的文字怎么写

> 给谁看：在本仓库写任何持久文字的人和 AI（文档、代码注释、提交信息、规则文件、发布说明）。回答：每种文字是干什么的、该怎么写、为什么 AI 总写成过程记录、怎么防。
> 总结提示词（`src/video_agent/prompts/`）和 skill 是产品的一部分，按它们自己的需求写（[summary-requirements.md](summary-requirements.md)），本篇只管它们的注释和提交信息。

## 一、问题

AI 在仓库里留下的文字，常常是过程的记录，而不是加工过的成品：

| 地方 | 表现 |
|---|---|
| 文档 | 抄用户原话；按时间记讨论经过；按日期往后追加，规格变成日志；「Claude 判断，等用户定」之类的过程标记留在正文里；每句挂证据标签 |
| 代码注释 | 「用户某日：『……』」；讲当时怎么讨论的，不讲这段代码为什么这样写 |
| 提交信息 | 引用对话；把讨论过程当成改动说明 |
| 交接文档 | 每次会话往后追加，越写越长，和规格重复 |

共同点：写的是「发生了什么」，不是「现在什么是对的、要做什么」。

## 二、原因

用户的话是原料，规格是成品，中间要经过理解、消除歧义、和已有内容对齐、写成可检验的陈述、让用户确认。照抄和记过程，就是跳过了这一步：

1. 不加工的代价推到了以后：规格含糊的代价，要等后来的会话读到时才付，写的当下没有反馈。
2. 加工要承担判断的责任，照抄不用：怕歪曲用户的意思，在对话里是对的，搬到规格上就过头了。
3. 不理解也能写出像样的文字：照抄完全不需要理解。写不出自己的陈述句，说明还没理解，该问，而不是抄。
4. 仓库本身就是提示词：每次会话都会读到仓库里的文字，AI 照着已有的样式写；一处原话、一段过程记录会被后来的会话模仿。所以只知道规则不够，要清掉坏样本，并在写的当下检查。

## 三、每种文字是干什么的

| 文字 | 回答什么 | 写什么 | 不写什么 |
|---|---|---|---|
| 需求、设计、参考、运行、约定文档 | 现在什么是对的、要做什么 | 现在时的陈述句，可检验；用户定的写「（用户 YYYY-MM-DD 定）」；试过的做法写结论（做法、结果、为什么不用） | 原话、讨论经过、钟点、被推翻的旧说法、过程标记 |
| 代码注释 | 这段代码为什么这样写 | 技术原因、约束、坑；需要时指向文档的某一节 | 原话、讨论经过、谁哪天说了什么；出处（用户的决定连同「（用户 YYYY-MM-DD 定）」写在它所属的文档里，注释指向那一节） |
| 提交信息 | 改了什么、为什么 | 第一行概括改动；正文写要点和整理后的决定 | 引用对话；AI 署名 |
| 规则文件（`.claude/rules/`） | 必须怎么做 | 祈使句，一条一事 | 原话、背景故事 |
| 发布说明（`docs/releases/`） | 这一版给用户带来什么 | 给用户看的平白中文，含代码改动一节 | 套话、翻译腔 |
| `docs/user-notes/` | 用户亲手写的原始材料 | 原样 | ——（唯一允许原话的地方） |
| 对话 | 讨论本身 | 随意 | ——（不进仓库） |

只在两种地方标出处：用户做的决定，和 AI 的推断。别的不标。出处标在文档里，代码注释不标。

## 四、写的步骤（每条用户的话进仓库前）

1. 改写：写成一句完整的陈述句，中性视角，去掉口语和语气。
2. 可检验：写清怎样算满足；写不出来，说明还没理解。
3. 找歧义：有两种以上读法时，不选也不抄，写出自己的理解，标「（AI 理解，待确认）」，并在对话里问。
4. 对齐：和已有内容比，冲突的直接改掉旧的，重复的合并。
5. 放对地方：决定写进它所属的那篇，不另开记录。
6. 确认：重要的改写给用户看一遍；确认过的版本就是可信的记录。

## 五、从机制上防住

1. 规则自动加载：`.claude/rules/hard-requirements.md` 里有这一条，每次会话都在上下文里。
2. 检查脚本 `scripts/lint_writing.py`：扫文档、规则文件、代码注释（含多行文档字符串和块注释）和提交信息（发布检查记录 `release-log.md` 和发布说明只追加，不扫），找出归给用户的引语、「Claude 判断」这类过程标记、带钟点的过程记录、指向已归档旧文档的引用，以及代码注释里「谁哪天说了什么」的记录。接成钩子：
   - Claude Code（`.claude/settings.json`）：每次 Write、Edit 之后查刚写的文件，每次 Bash 之后查工作区里改过的文件，有问题就把要改的地方反馈给 AI；
   - git（`scripts/githooks/`，用 `sh scripts/githooks/install.sh` 装进 `.git/hooks/`，全局钩子会转过来）：pre-commit 查要提交的文件，commit-msg 查提交信息里的用户引语和 AI 署名；有问题就拒绝提交。
3. 会话里的自查：写完持久文字，按第四节过一遍。
