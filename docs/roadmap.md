# 远期方向

> 给谁看：要决定下一步做什么的人和 AI。回答：还没排期的方向、做之前要先满足什么。这里不是承诺；决定要做时写成 [requirements.md](requirements.md) 里的需求。

## 总结文章

设计已定（用户定），还没做。

### 一、需求

- 用同一套方法快速总结别人的文章，读者读总结代替读原文，大多不会再去读原文。
- 一篇总结里既有速览也有完整正文，和视频总结一样，不做「地图／完整」的开关。
- 输入可能是纯文字、带图的网页或 PDF，由 Agent 自己读。位置不用标得很细：按原文的章节标，不标页码。
- 用在别的 Agent 里，那里可能能运行代码，也可能不能；也可能经本程序；以后可能做成插件或 npx 包。

### 二、一篇文章总结由什么组成

| 节 | 写什么 |
|---|---|
| 元信息 | 类型、作者和身份、在哪里什么时候发表（链接）、主题和范围、预设；「需留意」只在文章对读者有要求时才有 |
| 概要 | 和视频的一样 |
| 要点 | 按文章的顺序，每条写出自哪一节（代替时间段） |
| 主线与单元 | 由程序照详细内容排（[summary-design.md](summary-design.md)「主线与单元和要点」） |
| 详细内容 | 正文，按文章的章节分段，章节标题当段名，不带时间范围；命题不另标位置；图表读进命题，按原文编号引用，没有编号就描述一下 |
| 需确认 | 和视频的一样 |

去掉：字幕改正、画面调整，以及一切关于画面和字幕的规则。

### 三、规则同源

把 `prompts/summary.md` 拆成两边共用的核心（总结给谁看、条目、标签、来源、关系、拓展和核对、命题怎么写、主线与单元、共用的自查）和各自的部分（视频：时间点、画面、字幕、课堂的需留意、模板；文章：位置、图表、模板）。视频模板和文章规则都由这些拼成：核心改一处，两边都变。`forest.py` 两边共用一个。

### 四、形态，按顺序做

1. **共用核心**：拆规则；视频模板拼出来实质不变；测试保证生成的文章规则和来源一致。
2. **单体 skill**（`skills/article-summary/`）：SKILL.md、拼好的文章规则，以及作为脚本的 `forest.py`（只用 Python 自带的 `re`）。能运行 Python 的 Agent 写完草稿后跑脚本排「主线与单元」，照它报的问题改；不能运行的照规则里附带的写法自己写这一节（1.4.1 那种由模型写的森林，出错率更高）。
3. **接入本程序**：一个命令（例如 `video-agent article <网址或文件>`），每篇文章一个文件夹，复用导入、版本、检查和排森林；文章仍由 Agent 读。桌面程序先不动。
4. **插件和 npx**：Claude Code 插件就是同一个 skill 文件夹换个打包；npx 是 Node 的，要把排森林的程序再写一份 JavaScript，或者调用 Python。现成的「用 npx 装 skill」的工具有没有、怎么用，没查过。

### 五、没做的

- 上面四种形态。
- 不能运行脚本时手写「主线与单元」的那份规则。
- 文章的「需留意」写什么、元信息要不要更多（例如文章自己对证据的说明），要拿真实文章试。
- 纯文字、带图、PDF 各找几篇试。

## 多种模板

自带的只有「标准」；按用户的需求再做别的。

## 分阶段接 claude、codex 命令行

- 这两个命令行都有自定义 agent、限制工具、接续对话的开关，满足 [ADR-0010](adr/0010-staged-through-agy.md) 对通道的要求。接之前先在 10 分钟片段上量外壳和质量。
